**🟡 Известный риск платформы.** «Управление торговым предприятием для Украины»
(ред. 1.2) — конфигурация старшего поколения (обычные формы, обычное приложение),
часто эксплуатируется в режиме совместимости с 8.2. Расширения конфигурации `.cfe`
поддерживаются с платформы **8.3.6+**, а полноценное добавление **HTTP-сервисов
внутри расширения** стабильно доступно с **8.3.9–8.3.10+**. Поэтому до подтверждения
версии платформы и режима совместимости **нельзя гарантировать**, что целевая
архитектура «расширение с HTTP-сервисами» реализуема без изменения основной
конфигурации. → см. `RISKS.md` (R-01) и обходной путь ниже.

**Обходной путь (если расширение с HTTP-сервисом невозможно):**
1. Тонкая доработка в основной конфигурации: добавить только модуль HTTP-сервиса
   (минимально инвазивно, по согласованию со специалистом 1С); либо
2. Внешняя обработка + фоновое задание, публикующее обмен через промежуточный
   регистр/файловый шлюз; либо
3. Отдельный опубликованный **Web-сервис (SOAP)** вместо HTTP-сервиса.
   Выбор фиксируется в `DECISIONS.md` после подтверждения версии.

### B.5. Правила учёта, которые обязательно выяснить

- Правило расчёта **доступного остатка** (остаток − резерв; учитывается ли «в пути»).
- Правило **резервирования** (через ЗаказПокупателя? отдельный резерв? по складу?).
- Правило **снятия резерва** (ручное / по отгрузке / по отмене заказа).
- Правило создания **Заказа покупателя** (обязательные реквизиты, договор, организация).
- Правило создания и **проведения Реализации** (списание по партиям, себестоимость).
- Правило проведения **Возврата** (влияние на партии/себестоимость).
- Разрешены ли **отрицательные остатки** (запрет → отказ проведения при нехватке).
- Работа с **сериями/партиями** и **себестоимостью** (FIFO/средняя).
- **Закрытые периоды** (запрет проведения задним числом).
- Используемые **валюты и курсы** (мультивалютность заказов).

## Раздел C. Обследование KeyCRM (по актуальной OpenAPI)

**Источник фактов:** официальная документация KeyCRM (`docs.keycrm.app`,
`help.keycrm.app`) и публичный SDK, зеркалящий OpenAPI. Базовый URL API:
**`https://openapi.keycrm.app/v1`** ✅. Авторизация — Bearer-токен ✅.

### C.1. Лимиты и общие правила

| Параметр | Значение | Статус |
|---|---|---|
| Лимит запросов | **60 запросов/мин на один API-ключ** | ✅ |
| Пагинация | `limit` (обычно ≤50, дефолт 15), `page` | ✅ |
| Фильтры | `filter[...]`, `sort` | ✅ |
| Расширение ответа | `include=...` (перечень зависит от ресурса) | ✅ |
| Массовые операции | `POST /order/import` (до 50), `POST /products/import` (до 100) | ✅ |

→ Требование ТЗ п.15 «ограничение частоты запросов»: клиент KeyCRM обязан
соблюдать 60 rpm с очередью и backoff. Актуальный лимит подтвердить в кабинете
(зависит от тарифа) — ❓ BLK-001.

### C.2. Ресурсы и эндпоинты (подтверждено по SDK/OpenAPI)

**Группы API:** Buyer, Company, CustomFields, Offer, Order, Payments, Pipelines,
Products, Storage. ✅

**Товары (Products)** ✅
- `POST /products`, `GET /products`, `GET /products/{id}`, `PUT /products/{id}`
- `POST /products/import` (до 100), `POST /products/{id}/offers` (варианты, до 100)
- `POST /products/categories`, `GET /products/categories`
- Поля модели: `product_id`, `name`, `category_id`, `sku`, `barcode`, `prices`,
  `unit`/`measure`, `is_archived`, `offers`, `include=custom_fields`.

**Варианты/остатки (Offers)** ✅
- `GET /offers` (варианты; `include=product`; `filter` по `id`/`offers_id`/`sku`)
- `GET /offers/stocks` — **остатки по складам** (чтение)
- `PUT /offers/stocks` — **обновление остатков по складам** (запись)
- `PUT /offers` — правка варианта (идентификация по `id` или `sku`)
- Поля: `id`, `sku`, `barcode`, `price`, `purchased_price`, остаток/`quantity`,
  `reserve`, `warehouse_id`, `properties`/вариации.

**Покупатели (Buyer)** ✅
- `POST /buyer`, `GET /buyer`, `GET /buyer/{id}`, `PUT /buyer/{id}`, `POST /buyer/import`
- Поля: `name`, `phones`, `emails`, `addresses`, `company`, `manager`
- `include=manager,shipping,company,loyalty,custom_fields`

**Заказы (Order)** ✅
- `POST /order`, `GET /order` (`include,filter,sort`), `GET /order/{id}`, `PUT /order/{id}`
- `POST /order/import` (до 50)
- Оплаты: `POST /order/{id}/payment`, `PUT /order/{id}/payment/{paymentId}`
- Расходы: `POST /order/{id}/expense`, `PUT /order/{id}/expense/{expenseId}`
- Файлы: `POST|DELETE /order/{id}/attachment/{fileId}`
- Теги: `POST|DELETE /order/{id}/tag/{tagId}`
- **Справочники (то, что требует аудит ТЗ 3.2):**
  - `GET /order/status` — **статусы заказов** ✅
  - `GET /order/product-status` — статусы товара (для сборки) ✅
  - `GET /order/payment-method` — **методы оплаты** ✅
  - `GET /order/delivery-service` — **службы доставки** ✅
  - `GET /order/source` — **источники заказов** (Instagram и т.д.) ✅
  - `GET /order/expense-type`, `GET /order/tag` ✅

**Оплаты (Payments), Компании (Company), Кастомные поля (CustomFields),
Воронки/статусы (Pipelines), Файлы (Storage)** — присутствуют ✅
(детальные поля уточнить живыми запросами при наличии ключа).

### C.3. Остатки — как устроено (важно для правила «единого остатка»)

- **API `/offers/stocks`** — даёт и принимает остатки **по складам** (есть `warehouse_id`). ✅
  → это основной канал синхронизации 6 мест хранения из 1С в KeyCRM.
- **Вебхук изменения остатков** отдаёт `offer_id`, `sku`, `in_stock`, `in_reserve`
  и **агрегирует** выбранные склады (НЕ по каждому складу отдельно). ✅
  Доступный остаток = `in_stock − in_reserve`. ✅
  → **Ограничение:** для пер-складской картины в KeyCRM опираемся на `GET /offers/stocks`,
  а не на payload вебхука. Зафиксировано в `KEYCRM_LIMITATIONS.md` (LIM-01).

### C.4. Кастомные поля заказа ✅
Типы: Text, Select, Textarea, Link, Integer, Float, Date, Datetime, Toggle.
Все доступны через API. → используем для служебных полей интеграции
(номер документа 1С, GUID, статус проведения, причина ошибки, correlation-id).

### C.5. Что по KeyCRM определяется ТОЛЬКО живым API/кабинетом (❓ BLK-001)

Значения ниже специфичны для аккаунта InterTex-Fabric и не выводятся из документации —
их снимаем реальными GET-запросами при получении ключа:
- фактический список **источников** (`GET /order/source`);
- фактическая цепочка **статусов** и воронок (`GET /order/status`, Pipelines);
- **склады** аккаунта и их `warehouse_id` (из `/offers/stocks`);
- **пользователи** и **роли** (менеджеры, удалённые, сборщики);
- **методы оплаты** (`GET /order/payment-method`);
- **службы доставки** (`GET /order/delivery-service`, Нова Пошта/NovaPay);
- **кастомные поля** и их коды;
- фактическая структура **вариантов** и **единиц измерения** товаров;
- актуальный **лимит API** по тарифу;
- перечень доступных **событий вебхуков** и точные имена action’ов.

## Раздел D. Итоги обследования (предварительно, до получения доступов)

**Подтверждено фактами:**
1. KeyCRM API покрывает все нужные сущности (товары, варианты, остатки по складам,
   покупатели, заказы, оплаты, статусы, источники, доставки, кастомные поля).
2. Остатки по складам доступны через `/offers/stocks` (чтение и запись).
3. Идемпотентность и связка по ID реализуемы: у товара — `sku`/`offer_id`,
   у заказа — `id`, у покупателя — `id`+телефон/email, кастомные поля под GUID 1С.

**Найденные ограничения (полный список — `KEYCRM_LIMITATIONS.md`):**
- LIM-01: вебхук остатков агрегирует склады → пер-склад берём из `/offers/stocks`.
- LIM-02: лимит 60 rpm → обязательны очередь и backoff.

**Главные риски обследования (полный список — `RISKS.md`):**
- R-01: совместимость платформы 1С с расширением `.cfe` + HTTP-сервисом (см. B.1).
- R-02: правила резерва/списания/себестоимости УТП неизвестны → блокируют проектирование проведения.
- R-03: запрет отрицательных остатков и закрытые периоды → обработка отказов проведения.
- R-12 🔴: базовый ключ сопоставления — штрихкод, но наличие `2000000…` в регистре
  Штрихкодов 1С **не подтверждено** (ГЕЙТ, DEC-011); fallback по артикулу ~25% и не готов.

**Вывод:** обследование стороны KeyCRM выполнимо и в значительной части выполнено по
документации. Обследование стороны 1С **заблокировано** отсутствием доступа и требует
данных по `04_DATA_REQUEST.md`. К реализации (Этап 2) переходим после закрытия
BLK-002/BLK-003 и подтверждения архитектуры со стороны 1С.
