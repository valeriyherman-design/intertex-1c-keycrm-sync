# 04. Запрос данных для получения из 1С и KeyCRM

**Проект:** KeyCRM ↔ 1С:УТП · **Дата:** 2026-07-16 · **Этап:** 1
**Назначение:** снять блокеры BLK-001/BLK-002/BLK-003 и перейти к Этапу 2.

> ⚠️ **Пароли, API-ключи и токены НЕ передавать в текстовом виде** в переписке/файлах.
> Их вводят напрямую в мастере настройки при установке (ТЗ п.17, устав).

## Часть 1. Данные от специалиста 1С (закрывает BLK-002/BLK-003)

### 1.1. Среда (для `handover-1c/02_1C_ENVIRONMENT.md`)
1. Скриншот окна **«О программе»** (версия платформы + релиз конфигурации).
2. Точное **название и релиз** конфигурации (УТП ред. ?).
3. **Режим совместимости** конфигурации.
4. База **файловая или клиент-серверная**; если серверная — **СУБД**.
5. **ОС** сервера 1С.
6. Опубликована ли база (**IIS / Apache**), адрес публикации.
7. Конфигурация **на поддержке** или снята с поддержки.
8. Разрешена ли установка **расширений `.cfe`**; возможность **HTTP-сервисов** в расширении.
9. Возможность выполнения **фоновых заданий**.
10. Перечень уже существующих **доработок и расширений**.
11. Порядок и расписание **резервного копирования**.
12. Контакт ответственного за рабочую базу.

### 1.2. Тестовый контур (BLK-003)
13. **Тестовая копия базы** (без лишних персональных данных) или отдельный
    тестовый контур с веб-публикацией.
14. Доступ к **Конфигуратору** тестовой базы (или согласованный способ установки `.cfe`).
15. Отдельный **пользователь интеграции** с минимальными правами (создаётся при установке).

### 1.3. Метаданные и учётные правила (для `01_SYSTEM_AUDIT.md` разделы B.2–B.5)
16. Точные **имена метаданных** справочников: Номенклатура, Характеристики,
    Единицы измерения, Штрихкоды, Склады, Контрагенты, Контактные лица, Договоры,
    Организации, Типы цен, Валюты, Пользователи.
17. Точные **имена документов**: Заказ покупателя, Реализация, Возврат от покупателя,
    Перемещение, Поступление, Списание/Оприходование, кассовые, банковские.
18. Точные **имена регистров**: остатки, резервы, заказы, цены, партии, взаиморасчёты.
19. Где хранятся **штрихкоды** и **характеристики** (реквизит/регистр/справочник).
20. Правило расчёта **доступного остатка**.
21. Правило **резервирования** и **снятия резерва**.
22. Правила создания и проведения **Заказа покупателя** (обязательные реквизиты:
    Организация, Договор, Склад, вид цены — что обязательно?).
23. Правила создания и проведения **Реализации** (списание, себестоимость, партии).
24. Правила проведения **Возврата** и **Перемещения**.
25. Разрешены ли **отрицательные остатки**; поведение при нехватке.
26. Работа с **партиями/сериями** и метод **себестоимости** (FIFO/средняя).
27. **Закрытые периоды** и запрет проведения задним числом.
28. Используемые **валюты и курсы**.
29. **Примеры реальных документов** каждого типа (обезличенные) — для контракта API.
30. Список типичных **ошибок проведения**, которые видит оператор.

### 1.4. Справочные списки для mapping (для `02_ENTITY_MAPPING.md` Таблица 4)
31. Список **складов/мест хранения** (6 шт.): код + GUID + название.
32. Список **организаций**; **типов цен**; **валют**; **единиц измерения**.
33. Список **пользователей/менеджеров** (для сопоставления с KeyCRM).

## Часть 2. Данные из KeyCRM (закрывает BLK-001)

**Нужно:** API-ключ (передать безопасно при настройке) + тариф/лимиты.
После получения ключа снимаются реальными GET-запросами (read-only, без изменений):

| # | Что получить | Метод API | Для чего |
|---|---|---|---|
| 1 | Источники заказов | `GET /order/source` | сопоставление каналов (Instagram и т.д.) |
| 2 | Статусы заказов | `GET /order/status` | маппинг 19 бизнес-статусов |
| 3 | Статусы товара | `GET /order/product-status` | процесс сборки |
| 4 | Методы оплаты | `GET /order/payment-method` | таблица оплат |
| 5 | Службы доставки | `GET /order/delivery-service` | ТТН, Нова Пошта/NovaPay |
| 6 | Типы расходов | `GET /order/expense-type` | учёт расходов заказа |
| 7 | Кастомные поля | `GET /custom-fields` (CustomFields API) | служебные поля интеграции |
| 8 | Категории товаров | `GET /products/categories` | маппинг категорий |
| 9 | Товары | `GET /products?include=custom_fields` | структура каталога |
| 10 | Варианты | `GET /offers?include=product` | sku/barcode/цены/вариации |
| 11 | Остатки по складам | `GET /offers/stocks` | **список складов + `warehouse_id`** |
| 12 | Покупатели | `GET /buyer?include=manager,company` | структура карточки |
| 13 | Заказы (образцы) | `GET /order?include=...&limit=5` | реальная структура заказа |
| 14 | Пользователи/менеджеры и роли | из аккаунта / связанных полей | сопоставление менеджеров, права |
| 15 | Настройки вебхуков и список событий | кабинет → интеграции | перечень доступных событий/action |
| 16 | Фактический лимит API по тарифу | кабинет/документация | параметры rate-limit клиента |

> Пункты 14–15 частично снимаются из административного кабинета KeyCRM (не только API).

## Часть 3. Что разблокируется после получения данных

| Получены | Разблокируется |
|---|---|
| API-ключ KeyCRM (ч.2) | реальное снятие статусов/складов/полей; Этап 2 (прототип чтения) |
| Версия платформы + режим совм. (ч.1.1) | выбор архитектуры стороны 1С (расширение vs альтернатива), R-01 |
| Тестовая база (ч.1.2) | интеграционные и приёмочные тесты |
| Учётные правила (ч.1.3) | проектирование проведения документов и обработки ошибок |
| Справочники 1С (ч.1.4) | заполнение mapping-таблиц, Этап 3 (каталог/остатки) |

**До получения этих данных** ведём: контракт API 1С (как требование к стороне 1С),
каркас middleware на моках, шаблоны mapping и тест-кейсов — не трогая рабочую 1С.
