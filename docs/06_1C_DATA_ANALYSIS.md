## 2. Единицы измерения и дробность

`пар` 154, `рул` 19, `кг` 1, пусто 175.

⚠️ **Находки:**
- **Дробное количество — не только у метров.** В остатках есть `20.25 пач`,
  `18.66 пар`, `3.41 пач`. → дробность (3 знака) нужна для ВСЕХ единиц, не только тканей.

## 3. 🔴 Сопоставление товаров 1С ↔ KeyCRM — ГЛАВНЫЙ РИСК Этапа 3

**Три разных идентификатора:**

| Система | Идентификатор | Пример |
|---|---|---|
| 1С Код | внутренний | `3869` |
| 1С Артикул | 6-значный (94% заполнен) | `388168`, `375665` |
| KeyCRM SKU | **сгенерированный штрихкод EAN**, последовательный (+7) | `2000000310039`, `…046`, `…053` |

**Проверка (факт):** штрихкодов `2000000…` в выгрузках 1С — **0**.
13-значных чисел почти нет. → SKU KeyCRM, судя по выгрузке, **отсутствуют в
номенклатуре 1С** (сгенерированы на стороне KeyCRM/при импорте).

**Что реально совпадает:** **артикул-код в названии** формата
`[A-Z]{2}\d{4,6}(\.\d{2,3})+` (AM52231.003, RJ11235.002.05, AB13316.102) —
найдено **929** таких кодов в 1С и они же зашиты в названия товаров KeyCRM
(«Шантилье **AM52231.003**_(1)»). Плюс характеристика/цвет (Молочный/Белый).

**Следствие для стратегии (DEC-011):**
1. Приоритет 1 — по **штрихкоду** (если 1С всё же хранит `2000000…` в регистре
   Штрихкодов — проверить, см. блокер ниже). Быстро и точно.
2. Приоритет 2 (fallback) — по **артикул-коду из названия + характеристика**.
   Требует нормализации («Шанталье»/«Шантилье», суффикс `_(1)`, регистр) и
   разового отчёта расхождений на подтверждение.
3. Что не сопоставилось — в отчёт, товар в заказе с таким SKU → `SKU_NOT_FOUND`
   (заказ не проводится молча).

> Обработка `.epf` уже ищет по регистру Штрихкодов, затем по коду; **добавить
> ветку поиска по артикул-коду** (fallback) — после подтверждения блокера.

## 4. Качество каталога (влияет на Этап 3)

- Явный мусор/тест в номенклатуре: `__фііфвфів`, `-вапифвпфа`, `========`,
  `------------`, `0.9`, `1`, `_вільно`, `_Інші тканини_ (*)` — ~11 очевидных,
  плюс группы-заглушки. При выгрузке каталога в KeyCRM — **фильтровать**
  (не переносить помеченные на удаление / служебные группы).
- ~3777 позиций номенклатуры; в KeyCRM ~5399 вариантов (offers) — разница за счёт
  характеристик (цветов) и, возможно, ранее импортированных/дублей.

## 5. Что нужно от 1С для закрытия риска сопоставления (блокер)

**Экспорт штрихкодов из 1С:** Номенклатура + Характеристика + **Штрихкод**
(регистр Штрихкоды). Цель — проверить, содержит ли 1С те же `2000000…`, что
KeyCRM использует как SKU:
- если **да** → сопоставление по штрихкоду, тривиально;
- если **нет** → сопоставление по артикул-коду+характеристике (fallback),
  и отдельно решить, нужно ли **записать штрихкоды KeyCRM в 1С** (backfill),
  чтобы дальше работать по штрихкоду.

Альтернатива экспорту — проверить это же одним запросом обработки `.epf` к
регистру Штрихкодов на тестовой базе (когда будет доступ).
