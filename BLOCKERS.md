## BLK-003 🔴 Тестовый контур 1С

- **Что отсутствует:** тестовая копия базы (без лишних перс. данных) или отдельный
  тестовый контур с веб-публикацией.
- **Где взять:** специалист 1С готовит копию рабочей базы.
- **Кто предоставляет:** специалист 1С / администратор.
- **Формат:** доступ к опубликованной тестовой базе (URL + пользователь интеграции).
- **Зачем:** без тестовой базы невозможны интеграционные и приёмочные тесты —
  а задача считается выполненной только после реальных тестовых сценариев.
- **Можно без него:** unit-тесты middleware на моках 1С.
- **Заблокировано:** end-to-end сценарии, проверка идемпотентности на реальных документах.

## BLK-004 🔴 Площадка размещения интеграционного сервиса

- **Что отсутствует:** решение — где крутится middleware (Windows Server рядом с 1С /
  отдельный Linux-хост / контейнер), доступ по HTTPS, доменное имя/сертификат.
- **Где взять:** администратор инфраструктуры заказчика.
- **Кто предоставляет:** DevOps/администратор заказчика.
- **Формат:** параметры хоста + сетевой доступ 1С ⇄ middleware ⇄ KeyCRM.
- **Зачем:** вебхуки KeyCRM должны приходить на публичный HTTPS-эндпоинт;
  middleware должен видеть HTTP-сервисы 1С.
- **Можно без него:** локальная разработка и тесты.
- **Заблокировано:** пилот, промышленная установка.
