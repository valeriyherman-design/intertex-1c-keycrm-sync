# 05. Контракт HTTP API 1С (для расширения .cfe)

**Версия контракта:** 0.1-draft · **Дата:** 2026-07-16
**Статус:** проект — финализируется после подтверждения среды 1С (BLK-002)
**Машиночитаемая спецификация:** `openapi-1c-integration.yaml` (рядом)

Это контракт, который обязано реализовать расширение 1С:УТП. Потребитель —
интеграционный сервис (middleware .NET 8). Направление вызовов: **только
middleware → 1С** (1С никуда не звонит сама).

---

## 1. Общие правила

| Параметр | Значение |
|---|---|
| Протокол | HTTPS (самоподписанный сертификат допустим в тестовом контуре) |
| Базовый путь | `/hs/keycrm/v1` (HTTP-сервис расширения) |
| Формат | JSON, UTF-8 |
| Аутентификация | HTTP Basic — отдельный пользователь 1С «ИнтеграцияKeyCRM» с минимальными правами |
| Валюта | **Все суммы — USD** (DEC-008). Поле `currency` всегда `"USD"`; иное значение → ошибка `CURRENCY_NOT_SUPPORTED` |
| Количества | `number` с дробной частью (ткани в метрах: `12.5`); точность — 3 знака |
| Даты | ISO 8601 (`2026-07-16T10:30:00Z`) |
| Идемпотентность | Заголовок **`X-Idempotency-Key`** обязателен для всех POST. 1С хранит ключи в регистре `ВнешниеИдентификаторыKeyCRM`; повтор с тем же ключом возвращает сохранённый результат, НЕ создаёт второй документ |
| Тайм-аут | Рекомендуемый клиентский тайм-аут 60 с; операции проведения — 120 с |
| Повторные вызовы | Любой метод безопасно повторяем (идемпотентность обязательна на стороне 1С) |
| Тестовый режим | Заголовок `X-Dry-Run: true` → валидация и формирование ответа **без записи/проведения** документов (ТЗ п.15) |

### 1.1. Формат ошибки (единый для всех методов)

```json
{
  "success": false,
  "error": {
    "code": "INSUFFICIENT_STOCK",
    "message": "Недостатньо залишку: Шантилье RS32039 — потрібно 12.5 м, доступно 8.2 м",
    "details": [
      { "sku": "2000000310213", "requested": 12.5, "available": 8.2, "warehouse_id": "wh-guid" }
    ],
    "retryable": false
  }
}
```

### 1.2. Коды бизнес-ошибок

| Код | HTTP | Retryable | Описание |
|---|---|---|---|
| `AUTH_FAILED` | 401 | нет | неверные учётные данные |
| `VALIDATION_ERROR` | 400 | нет | не заполнены обязательные поля |
| `SKU_NOT_FOUND` | 404 | нет | SKU не сопоставлен с номенклатурой |
| `WAREHOUSE_NOT_FOUND` | 404 | нет | склад не найден по GUID |
| `CUSTOMER_NOT_FOUND` | 404 | нет | контрагент не найден |
| `ORDER_NOT_FOUND` | 404 | нет | заказ 1С по keycrm_order_id не найден |
| `INSUFFICIENT_STOCK` | 409 | нет | нехватка остатка для резерва/списания |
| `ALREADY_PROCESSED` | 200 | — | повтор идемпотентного запроса (возвращается прежний результат) |
| `ORDER_MODIFIED` | 409 | нет | состав заказа 1С отличается от переданной контрольной суммы |
| `PERIOD_CLOSED` | 409 | нет | закрытый период — проведение запрещено |
| `POSTING_ERROR` | 422 | нет | ошибка проведения (текст 1С в message) |
| `CURRENCY_NOT_SUPPORTED` | 422 | нет | валюта ≠ USD (DEC-008) |
| `LOCKED` | 423 | **да** | объект заблокирован другим сеансом — повторить позже |
| `INTERNAL_ERROR` | 500 | **да** | непредвиденная ошибка 1С |

## 2. Методы

### 2.1. `GET /health` — проверка доступности
**Ответ 200:**
```json
{ "status": "ok", "config": "УТП для Украины, ред. X.X", "extension_version": "0.1.0", "time": "2026-07-16T10:30:00Z" }
```

### 2.2. `GET /warehouses` — склады (6 мест хранения)
**Ответ 200:**
```json
{ "success": true, "data": [
  { "guid": "xxxx-...", "code": "000000001", "name": "Магазин №4", "is_active": true }
]}
```

### 2.3. `GET /products?updated_since=...&page=N&limit=100` — каталог
Возвращает номенклатуру с характеристиками, штрихкодами, единицами и ценами.
**Ответ 200 (элемент):**
```json
{
  "guid": "nom-guid", "code": "УТ000123", "name": "Шантилье RS32039",
  "category": "Шантильї різні", "unit": "м", "unit_allows_fraction": true,
  "is_archived": false,
  "variants": [
    { "characteristic_guid": "chr-guid", "characteristic": "Молочный",
      "sku": "2000000310213", "barcode": "2000000310213",
      "prices": [ { "price_type": "Розничная", "price": 6.60, "currency": "USD" } ],
      "purchased_price": 6.00 }
  ]
}
```
Пагинация: `meta: { page, limit, total }`. `updated_since` — по версии данных 1С.

### 2.4. `GET /stocks?warehouse_guid=...&updated_since=...&page=N` — остатки
**Ответ 200 (элемент):**
```json
{ "sku": "2000000310213", "warehouse_guid": "wh-guid",
  "quantity": 25.700, "reserved": 12.500, "available": 13.200 }
```
Правило расчёта `available` — фиксируется после обследования УТП (B.5).

### 2.5. `POST /customers` — найти или создать контрагента
Анти-дубли: поиск по `keycrm_buyer_id` → телефону(ам) → email. Создание только
если не найден.
**Запрос:**
```json
{ "keycrm_buyer_id": 4075, "full_name": "Віра Філіпова",
  "phones": ["+380678733123"], "emails": [], "comment": "" }
```
**Ответ 200/201:**
```json
{ "success": true, "data": { "guid": "ctr-guid", "created": false,
  "matched_by": "phone" } }
```

### 2.6. `POST /orders` — создать/обновить Заказ покупателя
Идемпотентность по `keycrm_order_id` (один заказ KeyCRM = один ЗаказПокупателя).
Повторный вызов с изменённым составом — обновляет документ (если не было
реализации; иначе `ORDER_MODIFIED`).
**Запрос:**
```json
{
  "keycrm_order_id": 1780,
  "customer_guid": "ctr-guid",
  "warehouse_guid": "wh-guid",
  "manager_keycrm_id": 3,
  "currency": "USD",
  "comment": "коментар менеджера",
  "items": [
    { "sku": "2000000310213", "quantity": 12.5, "price": 6.60,
      "discount_percent": 0, "sum": 82.50 }
  ],
  "items_checksum": "sha256-hex"
}
```
**Ответ 201:**
```json
{ "success": true, "data": { "order_guid": "doc-guid",
  "order_number": "УТ-00001780", "order_date": "2026-07-16T10:30:00Z" } }
```

### 2.7. `POST /orders/{keycrm_order_id}/reserve` — резервирование
**Запрос:** `{ "warehouse_guid": "wh-guid" }` (резерв всего состава заказа).
**Ответ 200:** остатки по позициям после резерва.
**Ошибка нехватки:** `INSUFFICIENT_STOCK` с details по каждой дефицитной позиции
(sku, requested, available) — фиктивный резерв не создаётся (ТЗ п.8).

### 2.8. `DELETE /orders/{keycrm_order_id}/reserve` — снятие резерва
Идемпотентно: снятие уже снятого резерва → `success: true, "already": true`.

### 2.9. `POST /orders/{keycrm_order_id}/ship` — реализация (списание)
Предусловия на стороне 1С: заказ существует, резерв есть, состав не изменился
(`items_checksum` сверяется), период открыт.
**Запрос:**
```json
{ "items_checksum": "sha256-hex", "post_document": true }
```
**Ответ 201:**
```json
{ "success": true, "data": {
  "realization_guid": "real-guid", "number": "УТ-00000456",
  "date": "2026-07-16T12:00:00Z", "posted": true } }
```
Ошибки: `ORDER_MODIFIED`, `INSUFFICIENT_STOCK`, `PERIOD_CLOSED`, `POSTING_ERROR`.
Повтор с тем же `X-Idempotency-Key` → тот же документ, второго списания нет.

### 2.10. `POST /orders/{keycrm_order_id}/return` — возврат
Исходная реализация НЕ удаляется (ТЗ п.13).
**Запрос:**
```json
{ "items": [ { "sku": "2000000310213", "quantity": 2.5 } ],
  "reason": "брак", "full_return": false }
```
**Ответ 201:** guid/номер документа возврата, `posted: true`.

### 2.11. `POST /payments` — регистрация оплаты
Идемпотентность по `keycrm_payment_id`.
**Запрос:**
```json
{ "keycrm_payment_id": 1442, "keycrm_order_id": 1780,
  "amount": 45.00, "currency": "USD", "method": "credit_card",
  "date": "2026-07-15T12:40:00Z" }
```
**Ответ 201:** guid платёжного документа. Тип документа (ПКО/банк) — по таблице
соответствий методов оплаты (10 методов, см. снапшот §3).
Конфликт (расхождение сумм) → запись в журнал, без молчаливой перезаписи (ТЗ п.12).

### 2.12. `GET /orders/{keycrm_order_id}/status` — состояние документов
**Ответ 200:**
```json
{ "success": true, "data": {
  "order":       { "guid": "...", "number": "...", "posted": true },
  "reserve":     { "active": true, "quantity_total": 12.5 },
  "realization": { "guid": "...", "number": "...", "posted": true },
  "returns":     [ { "guid": "...", "number": "...", "posted": true } ],
  "payments":    [ { "guid": "...", "amount": 45.0 } ] } }
```

### 2.13. `GET /transfers?since=...` — проведённые перемещения (этап 1 — чтение)
Для обновления остатков двух складов в KeyCRM после перемещения, созданного в 1С
(ТЗ п.14). **Ответ:** список перемещений: guid, номер, дата, склад-отправитель,
склад-получатель, позиции (sku, quantity).

## 3. Матрица «статус KeyCRM → вызовы API 1С»

| Переход статуса (KeyCRM) | Вызовы 1С |
|---|---|
| → Проверка резерва | `POST /customers` → `POST /orders` → `POST .../reserve` |
| → Отмена (после резерва, до списания) | `DELETE .../reserve` |
| → Проверка перед списанием | `GET .../status` → `POST .../ship` |
| → Возврат | `POST .../return` |
| Оплата добавлена | `POST /payments` |
| Периодическая сверка | `GET /stocks`, `GET /transfers`, `GET /products` |

## 4. Что должен уточнить/подтвердить специалист 1С

1. Реализуемость HTTP-сервиса в расширении на фактической платформе (R-01).
2. Обязательные реквизиты ЗаказаПокупателя в их УТП (организация, договор, вид цены).
3. Правило расчёта `available` (п. 2.4) и механизм резерва (п. 2.7).
4. Соответствие 10 методов оплаты типам платёжных документов (п. 2.11).
5. Поведение при закрытом периоде и запрете отрицательных остатков.
6. Производительность `GET /products`/`GET /stocks` на каталоге ~5400+ вариантов.
