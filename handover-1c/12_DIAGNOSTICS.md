# 12. Диагностический пакет

Как разобрать инцидент и найти нужный заказ/документ.

## Где смотреть
- **Логи сервиса:** `logs/intertexsync-YYYYMMDD.log` (структурированные, ротация 30 дней).
  Секреты и перс. данные маскируются.
- **Служебная БД:** `data/intertexsync.db` (SQLite) — таблицы `events` (очередь),
  `conflicts` (журнал конфликтов), `mappings` (соответствия), `idempotency`,
  `pushed_stocks` (снапшот остатков).
- **Админ-панель** (этап 7): состояние подключений, очередь, ошибки, конфликты,
  ручной повтор, полная сверка.

## Пример успешной операции (лог)
```
INF Обработка события 5 webhook.order.change_order_status (попытка 1)
INF Заказ 1780 зарезервирован (1С УТ-00001780), dryRun=False
INF Заказ 1780 [reserve] → Success
```

## Пример ошибки (лог)
```
WRN Заказ 1780 [reserve] → InsufficientStock: Недостатньо залишку: {"sku":"2000000310213","requested":12.5,"available":8.2}
```

## Коды ошибок (полностью — `05_API_CONTRACT.md` §1.2)
| Код | Смысл | Повтор |
|---|---|---|
| `INSUFFICIENT_STOCK` | нехватка остатка | нет (в «Помилку») |
| `SKU_NOT_FOUND` | товар не сопоставлен | нет |
| `ORDER_MODIFIED` | состав изменён после резерва | нет |
| `PERIOD_CLOSED` | закрытый период | нет |
| `POSTING_ERROR` | ошибка проведения | нет |
| `CURRENCY_NOT_SUPPORTED` | валюта ≠ USD | нет |
| `LOCKED` | 1С занята | **да** (автоповтор) |
| `INTERNAL_ERROR` | непредвиденная | **да** |

## Найти заказ / документ
- **По ID заказа KeyCRM:** в логе `Заказ <id>`; в служебной БД `events.order_key = 'order:<id>'`;
  в 1С — значение свойства `KeyCRM_order` = `<id>` в `ЗначенияСвойствОбъектов`.
- **По номеру документа 1С:** в кастомном поле заказа KeyCRM «1С: Номер документа»
  и в логе `(1С <номер>)`.
- **Причина ошибки заказа:** кастомное поле «1С: Причина помилки» в KeyCRM + запись в
  `conflicts` служебной БД.

## Ручной повтор
- Из админ-панели: «Повторить событие» (событие из `Dead`/`Failed` → в очередь).
- Полная сверка остатков: `POST /admin/sync/stocks` (уважает DryRun).

## Собрать диагностический архив (для передачи)
- `logs/` за нужный период + выгрузка таблиц `events`, `conflicts` служебной БД +
  версия сервиса (`/health`) + скриншот ошибки в KeyCRM. Без секретов (маскированы).
