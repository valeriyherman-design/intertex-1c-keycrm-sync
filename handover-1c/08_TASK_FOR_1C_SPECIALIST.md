# 08. Техническое задание специалисту 1С

Работать **только на тестовой копии базы**. Порядок задач — сверху вниз.

---

## Задача 1. Проверить обследование
Сверить с фактической базой (файлы `03_1C_OBJECTS.md`, `04_ORDER_FLOW.md`):
- [ ] Точные имена справочников/документов/регистров (все `❓` в `03_1C_OBJECTS.md`).
- [ ] Правило расчёта доступного остатка и механизм резервирования.
- [ ] Правила проведения Реализации и Возврата.
- [ ] Обязательные реквизиты ЗаказаПокупателя, Контрагента.
- [ ] Влияние интеграции на существующий учёт (нет ли конфликтов с доработками).

## Задача 2. Собрать и установить обработку `ИнтеграцияKeyCRM.epf`
Исходник и инструкция — в `../onec/` (`ИнтеграцияKeyCRM_МодульОбъекта.bsl`,
`README_СБОРКА.md`).
- [ ] Сделать резервную копию тестовой базы.
- [ ] Собрать `.epf` из исходного модуля (Конфигуратор → Внешняя обработка).
- [ ] Пройти по ~15 меткам `ПРОВЕРИТЬ(УТП)` — сверить имена метаданных, синтакс-проверка.
- [ ] **Не менять основную конфигурацию** без согласования (обработка внешняя).
- [ ] Проверить COM-подключение (`README_СБОРКА.md` §3): `health`, `warehouses`.

## Задача 3. Настроить пользователя интеграции
Создать пользователя **«ИнтеграцияKeyCRM»** с МИНИМАЛЬНЫМИ правами:
- [ ] Чтение: Номенклатура, Характеристики, Штрихкоды, Склады, ЦеныНоменклатуры,
      остатки/резервы, Контрагенты, состояние документов.
- [ ] Создание/изменение: Контрагенты, ЗаказПокупателя, РеализацияТоваровУслуг,
      ВозвратТоваровОтПокупателя, ПриходныйКассовыйОрдер, значения свойств (внешние ID).
- [ ] **Запретить** всё, что интеграция не использует (администрирование, удаление
      данных, закрытие периодов, изменение конфигурации).

## Задача 4. Проверить бизнес-логику (на тестовой базе)
Прогнать сценарии (готовые запросы — `test-cases/`):
- [ ] Заказ поштучного товара (шт).
- [ ] Заказ ткани с дробным количеством (12.5 пог.м.).
- [ ] Заказ с характеристикой (цвет).
- [ ] Резерв; недостаточный остаток (ожидается `INSUFFICIENT_STOCK` с деталями).
- [ ] Снятие резерва; повторный запрос (идемпотентность — без дубля).
- [ ] Реализация; проверка проводок и движений регистров.
- [ ] Возврат (реализация не удаляется).
- [ ] Одновременная работа двух заказов на один товар (не должно быть двойного списания).
- [ ] Ошибка проведения; закрытый период (ожидается `PERIOD_CLOSED`).

## Задача 5. Подтвердить готовность
Заполнить и подписать `1C_ACCEPTANCE_CHECKLIST.md` — письменно подтвердить, что
обработка установлена, объекты выбраны верно, документы создаются корректно, проводки
верны, остатки не искажаются, резерв работает, дублей нет, производительность
приемлема, резервная копия сделана, план отката проверен.

---

### Если что-то не совпало
Любое расхождение (иное имя объекта, иной механизм резерва, иные обязательные
реквизиты) — зафиксировать в `1C_ACCEPTANCE_CHECKLIST.md` (раздел «Замечания») и
сообщить: обработка и/или контракт будут скорректированы. **Ничего не «подгонять»
молча** — расхождение по учёту важнее скорости.
