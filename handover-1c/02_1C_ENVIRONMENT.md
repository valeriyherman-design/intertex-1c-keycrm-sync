## Следствия для архитектуры (важно)

1. **Платформа 8.3.18** — сама по себе поддерживает расширения `.cfe` и HTTP-сервисы.
2. **НО: УТП ред. 1.2 — конфигурация эпохи 8.2** (обычные формы, обычное приложение).
   С высокой вероятностью **режим совместимости = 8.2.x** → в этом режиме
   **механизм расширений и HTTP-сервисы недоступны**, независимо от версии платформы.
   → критическая проверка №1 (см. ниже).
3. **Файловая база**:
   - фоновые задания работают только при запущенном клиентском сеансе;
   - веб-публикация возможна (Apache/IIS + модуль 1С), но добавляет хрупкости;
   - **COM-подключение (`V83.COMConnector`) работает надёжно** и не требует
     ни публикации, ни изменения конфигурации → сильный кандидат для транспорта.
4. Лицензий достаточно для выделенного соединения интеграции.

## Что осталось уточнить (❓)

1. **Режим совместимости конфигурации** — Конфигуратор → корень конфигурации →
   свойство «Режим совместимости». Определяет: расширение возможно или нет.
2. Снята ли конфигурация с поддержки / включена ли возможность изменения.
3. Список уже внесённых доработок (если были).
4. ОС сервера (предположительно Windows — путь `D:\...`) и характеристики машины.
5. Есть ли веб-публикация сейчас (вероятно нет).
6. Кто выполняет резервное копирование и по какому расписанию.
7. Может ли на этой же машине работать интеграционный сервис (.NET 8, Windows Service).

## Матрица вариантов транспорта «middleware ↔ 1С» (решение после проверки №1)

| Вариант | Условие | Плюсы | Минусы |
|---|---|---|---|
| A. Расширение `.cfe` + HTTP-сервис + публикация | режим совместимости ≥ 8.3.6 (маловероятно для УТП 1.2) | целевая архитектура ТЗ | почти наверняка недоступно без смены режима совместимости |
| B. **COM-коннектор** (`V83.COMConnector`) + внешняя обработка `.epf` | Windows, middleware на той же машине | без изменения конфигурации; без публикации; синхронно; классика для файловых УТП | привязка к Windows/COM; нужен контроль сеансов |
| C. Web-сервис SOAP в конфигурации + публикация | доступен и в режиме 8.2 | стандартная публикация | правка основной конфигурации + веб-сервер |
| D. Поднять режим совместимости до 8.3.x, затем вариант A | полное регрессионное тестирование УТП | открывает расширения | самый рискованный шаг для старой конфигурации |

**Предварительная рекомендация:** вариант **B** как основной (быстрый, без вторжения
в конфигурацию), с абстракцией коннектора в middleware, чтобы позже можно было
перейти на A/C без переписывания логики. Финальное решение — после проверки
режима совместимости (DEC-009).
