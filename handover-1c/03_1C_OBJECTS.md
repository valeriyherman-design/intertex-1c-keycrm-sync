# 03. Объекты 1С, используемые интеграцией

**Конфигурация:** УТП для Украины, ред. 1.2.35.1 (обычное приложение) · платформа 8.3.18.
Ниже — объекты, которые читает/пишет обработка `ИнтеграцияKeyCRM.epf`. Имена даны по
типовой линейке УТ 10.3/УТП; **каждое помеченное `❓` имя специалист 1С обязан сверить
с фактической конфигурацией** (в `.epf` соответствующие места отмечены `ПРОВЕРИТЬ(УТП)`).

Легенда доступа: **R** — читает, **W** — создаёт/пишет.

## Хранение внешних идентификаторов KeyCRM (БЕЗ изменения конфигурации)
Связь «сущность KeyCRM ↔ объект 1С» и служебные значения (чексумма состава) хранятся
через **типовой механизм свойств**:
- `ПланВидовХарактеристик.СвойстваОбъектов` — свойства `KeyCRM_buyer`, `KeyCRM_order`,
  `KeyCRM_ship`, `KeyCRM_payment`, `KeyCRM_order_checksum` (создаются обработкой при
  первом использовании);
- `РегистрСведений.ЗначенияСвойствОбъектов` — сами значения (ID KeyCRM).

❓ Специалист 1С сверяет точные имена плана видов характеристик и регистра значений
свойств (в УТП обычно `СвойстваОбъектов` / `ЗначенияСвойствОбъектов`). Если механизм
свойств в базе отключён/иной — согласовать альтернативу (доп. реквизит или отдельный
регистр сведений в расширении).

## Что читает / что пишет интеграция (сводка)
- **Читает:** номенклатуру, характеристики, штрихкоды, склады, цены, остатки, резервы,
  контрагентов, состояние документов.
- **Пишет:** контрагентов, заказы покупателя, реализации, возвраты, кассовые ордера,
  значения свойств (внешние ID). **Не трогает** закрытые периоды, себестоимость,
  партии напрямую — только через штатное проведение документов.
