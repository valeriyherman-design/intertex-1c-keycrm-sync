# 04. Схема работы заказа (KeyCRM ↔ 1С)

Пошагово: что происходит при обработке заказа. Реализовано в сервисе (`OrderProcessor`),
операции 1С — по контракту `05_API_CONTRACT.md`. Идемпотентность на каждом шаге.

## Правила-инварианты (соблюдаются кодом)
- **Резерв без частичных:** при нехватке хоть одной позиции резерв НЕ создаётся;
  заказ → «Помилка синхронізації» с точным дефицитом (SKU, требуется, доступно).
- **Списание только по сверке** состава (чексумма): изменённый после резерва заказ
  на списание не пройдёт (`ORDER_MODIFIED`).
- **Валюта только USD** (DEC-008): заказы из не-USD источников (Prom) → «Помилка».
- **Реализация не удаляется** при возврате (ТЗ п.13) — создаётся отдельный документ.
- **Транзиентные ошибки 1С** (блокировка/тайм-аут) → автоповтор с задержкой;
  бизнес-ошибки (нехватка, закрытый период) → без повтора, в «Помилку».
- **Повторный вебхук** не создаёт дубль документа и не списывает повторно.

## Данные, которые сервис ждёт от каждой операции 1С
Каждая операция возвращает JSON-конверт `{"success":true,"data":{…}}` или
`{"success":false,"error":{code,message,retryable,details}}`. Коды ошибок и структуры —
`05_API_CONTRACT.md` §1.2. Именно эти коды сервис различает (напр. `INSUFFICIENT_STOCK`
с `details` по позициям, `PERIOD_CLOSED`, `LOCKED` — повторяемая).

## Что сборщик видит / не видит (DEC-012)
- **Видит** (лист сборки, роль складовщика): № заказа, склад, штрихкод, **внутренний
  оригинальный код/название**, фото, цвет/характеристика, кол-во, ед. изм., комментарий.
- **НЕ видит:** закупочную цену, маржу, финансы, чужие заказы.
- Менеджеры и клиенты **не должны видеть** внутренний код (открытый под-вопрос DEC-012:
  сейчас он зашит в название товара KeyCRM — решить, менять ли отображение).
