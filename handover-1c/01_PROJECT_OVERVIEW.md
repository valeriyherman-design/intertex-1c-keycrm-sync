# 01. Обзор проекта (для специалиста 1С)

**Компания:** InterTex-Fabric · **Дата пакета:** 2026-07-16 · **Версия сервиса:** 0.1.0

## Что за бизнес
Продажа тканей, кружева (шантильї, гіпюр, макраме), фурнитуры и товаров свадебной
тематики. Часть товара — поштучно (шт, пар, пач), ткани/кружева — **в метрах с
дробным количеством** (пог.м., напр. 12.5 м). Заказы идут в основном через Instagram
и мессенджеры; есть сайт (OpenCart) и Prom.ua.

- **4 магазина + 2 склада = 6 мест хранения** (реальные имена — `06_MAPPING_TABLES.csv`):
  Магазин № 1, № 2, № 3 (Добробут), № 4 (Чагор), Склад Контейнер, Центральный склад.
- Основная сборка — из Магазина № 4 (Чагор), но отгрузка возможна с любого места.

## Цель интеграции
**KeyCRM — единый рабочий интерфейс** менеджеров, удалённых сотрудников и сборщиков.
**1С:УТП — учётное ядро** (склад + финансы, юридически значимые документы).
Менеджеры **не заходят в 1С** для обычной обработки заказа: клиент, заказ, резерв,
реализация, оплаты создаются в 1С автоматически по событиям из KeyCRM.

## Архитектура (кратко)
```
KeyCRM  ──Open API + вебхуки──►  Интеграционный сервис (.NET 8, Windows Service)
                                        │
                                        ▼  (COM: V83.COMConnector + внешняя обработка .epf)
                                   1С:УТП для Украины
```
Сервис не подключается к БД 1С напрямую — только через вашу обработку
`ИнтеграцияKeyCRM.epf` (экспортная функция `ВыполнитьОперацию`). Контракт операций —
`05_API_CONTRACT.md`.

## Что уже реализовано (на стороне сервиса, протестировано на моке 1С)
- Синхронизация остатков: Σ по 6 местам 1С → один склад KeyCRM «Основной» (агрегат).
- Цикл заказа: контрагент (анти-дубли) → заказ покупателя → резерв → реализация →
  отмена/возврат → оплаты. Идемпотентность, обработка ошибок, dry-run.
- Приём вебхуков, очередь с повторами, журнал конфликтов, нормализация названий.
- 60 автотестов; сквозной прогон на реальном заказе KeyCRM (в dry-run).

## Что ещё НЕ сделано / зависит от вас
- Подтверждение имён метаданных УТП (~15 меток `ПРОВЕРИТЬ(УТП)` в `.epf`).
- Правила проведения/резерва/себестоимости конкретно вашей базы.
- Подтверждение, что штрихкоды `2000000…` (SKU в KeyCRM) есть в регистре Штрихкодов 1С
  (ГЕЙТ сопоставления товаров, см. `07_DATA_REQUEST…`).
- Каталог товаров (номенклатура → KeyCRM) — реализуется после подтверждения ключа.

## Ключевые решения (полностью — `../DECISIONS.md`)
- **DEC-004:** 1С — единственный истинный остаток; KeyCRM хранит оперативную копию.
- **DEC-008:** валюта только USD; заказы Prom (UAH) пересчитываются вручную.
- **DEC-009:** транспорт — COM + внешняя обработка (без изменения конфигурации).
- **DEC-010:** KeyCRM = один склад = сумма 6 мест 1С.
- **DEC-011:** сопоставление товаров — по штрихкоду (базовый), артикул из названия (fallback).
